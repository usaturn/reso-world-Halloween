## 1. 受領と原本の保存

読み方:

- 頂点: Meshy のメッシュは UV の継ぎ目で頂点が分かれている（取り込み時の数）。溶接後は `bmesh.ops.remove_doubles(dist=1e-6)` の後。削減しないので、仕上げでは溶接しない
- 穴: 溶接後の開いた縁の輪の数。小さな飾りの縁で、見える穴にはなっていない（下の「透ける割合」がほぼ 0）
- 浮いた破片: ほかの塊から最大辺の 0.5% 以上離れた塊。M01 は看板の右上の小さな飾り（98 三角形、置いた後 9 cm）、M04 は帽子の左の飾り（132 三角形、4 cm）、M05_Canopy は帽子の横の星（224 三角形、16 cm）、M06 は 1〜2 三角形の切れ端 2 つ。どれも静的な飾りで、見た目の問題は小さい。M06 の切れ端は仕上げで消してよい
- 裏返り: `bmesh.ops.recalc_face_normals` が向きを変える面の数。M05_Canopy の 15477 面は、薄い殻の飾り帯で向きの判定が割れたもので、裏面を消した描画で透けも色の変化も 0.01% 未満なので、元の法線は正しい
- 透ける割合: 前後左右上下の 6 方向を Workbench で、裏面の表示あり・なしの 2 回描き、ありでは物が見えるのに、なしでは背景になる画素の割合（`measured.backface_check`）。ResoLoop の exporter は `doubleSided` を保持しないので、Resonite では「なし」の見え方になる

## 3. 確定値（`decided`・`derived`）

約束（`received.json` の `conventions`）:

- 変換は `p_local = Rz(yaw_deg) · scale · (p_source − origin_source)` をメッシュに適用する（オブジェクトの scale は 1 のまま、`docs/conventions.md` §1）
- 置いた後の正面（動く物は進む向き）を +Y にそろえた。+Y は Resonite の +Z（Slot の前方）なので、P3 で列車や魔女を経路に沿って向けるとき、Slot の前方をそのまま進む向きに使える。ワールドでの向きは `placement_hint.rotation_z_deg`（0 で北、90 で西、180 で南、-90 で東を向く）。M07 のパックの manifest の `front_axis: -Y` は使わない

### W01 の枠との照合

- M01 の通路 4.36 m は主動線（Route_South_Entrance_Approach、4.0 m）より広い。ただし W01 の `entrance.gate_position` (0,-44,0) は spawn と同じ点で、ゲートをそこに置くと spawn の clearance 3.0 m に柱（中心から ±2.2 m 以遠、奥行き ±1.31 m）が入る。推奨は spawn から北へ 4 m の y=-40（W02 が決める）
- 建物が地区の境界に収まる: M03 を (0,41.5) に置くと y 36.4〜46.6（B は 20〜48）、M04 を (38,0) に置くと x 35.3〜40.7（C は 20〜48）、M07 を (-38.5,0) に置くと x -42.3〜-34.7（E は -48〜-20）、M05 を (-10,-32) に置くと半径 4.76 m で x -14.8〜-5.2（D は -22〜22、主動線の縁 x=-2 にかからない）
- 高さ: W01 の landmark の `height_m`（A 12、B 20、D 12）は仮の値で、素材の高さ（M02 6.0 m + 器、M03 10.6 m、M05 は柱の原点から 9.35 m）とは違う。landmark の更新は W01 の所有なので変えていない

## 5. 削減の目標（`budget`）

- 三角形は削減しない（上限は確定版の数）。どれも 1.5〜4.2 万、合計約 27.3 万で、Spec §11 のとおり一律の上限で削らない。削減すると UV の作り直しと原本からの焼き直しが要り、色がにじむ・UV の使用率が落ちる危険がある（asakusa01 の経験）

## 7. 仕上げの共通処理（`modeling/meshy/`）

| ファイル | 役割 |
|---|---|
| `intake_inspect.py` | 検査と `measured`・`derived` の書き込み（Blender） |
| `review_views.py` | 確定値の寸法での 4 方向の確認画像（Blender、`modeling.lib.render` の Cycles） |
| `finish.py` | 1 行の仕上げ: 縮尺・原点・向きの適用、命名、画像の解像度の調整、export できる材質への変換、`.blend` と `meta.json` の保存（Blender） |
| `meshops.py`・`metrics.py`・`glb.py` | 共通の部品（取り込み・結合・溶接・形の検査・裏面の検査、行列と UV・開口の計算、GLB の JSON） |

`finish.py` の材質の変換: glTF の取り込みは金属と粗さを Separate Color ノード経由でつなぐが、`resoloop blender export --pack-pbr` はこれを受け付けない（「arbitrary RGB-to-value conversions are rejected」）。そこで金属・粗さの画像を G（粗さ）と B（金属）の 2 枚のグレースケール（Non-Color）に分けて、それぞれ入力に直接つなぐ。値の幅が 2/255 未満の画像は定数にする。

削減と焼き直しの処理は用意していない（5 の判断）。後で要る素材が出たら、asakusa01 の `assets/meshy/tools/finish.py`・`uvatlas_uv.py` を参考に、溶接（`remove_doubles(dist=1e-6)`）→ 削減 → open3d の UVAtlas で UV の展開（使用率の目安 60% 以上）→ 原本から Cycles の selected-to-active で焼き直し（2048 から）の順に `finish.py` へ足す。create-reso-world の `scripts/meshy.py` の `convert` は使わない（法線マップ付きの GLB を拒否する不具合、create-reso-world #85・usaturn/resoloop#17）。
