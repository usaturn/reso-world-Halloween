- `FixedCollision` は仮モデルと同じメッシュの資産を参照する自分の `StaticMesh` を持つ。仮モデルの見た目を消しても当たり判定は残る。仕上げた素材に合わせて当たり判定の形を変えるかは差し替えの子が決める（変えるなら `modeling/p2_static/colliders.py` の扱いを直し、同じキーの state で diff を確かめる）
- 差し替えの子は、地区のバンドルの中の仮モデルの扱いを変える（例: 地区の export から仮モデルを外し、仕上げた素材を別の宣言で同じ場所に置く）ときに、その地区の宣言を作り直して diff の対象が仮モデルの範囲だけかを確かめる。地区の宣言を作り直さずに別の宣言から地区の Slot を消すと、次の地区の apply が作り直す
- 仕上げた素材の ID・向き・置き方は `docs/p1-handoff.md` 5 章と 8 章の 6〜8

### 3.2 export と apply の手順

統合の記録 7 章。要点だけ:

1. `docs/p1-handoff.md` 6 章の手順で各キーの `.blend` を作る
2. `uv run python modeling/p2_static/export_p2.py --url <URL>`（新しい `exports/p2_static/<key>-<UTC>/`）
3. apply の前に `resoloop import <W08 の root の ID> --output <親の checkout>/tmp/w08/<新しいディレクトリ>` でスナップショット
4. キーごとに `resoloop diff <出力先>/p2.apply.json --state <state> --brief --report <新しいファイル> --json` で対象を確かめてから `resoloop apply`。2 回目の diff が 0 になることを確かめる
5. `uv run python modeling/p2_static/verify_live.py --url <URL> --raw-out <Git の外> --output review/p2_static/live_checks.json`

### 3.4 保存の後の最初の apply（差し替えの子への注意）
