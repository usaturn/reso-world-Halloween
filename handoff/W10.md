## 6. 次の子への注意と、残りの先行 8 種類の進め方

### 6.1 注意

- **ワールドを前面に出す**: 背面では `Spinner` も ProtoFlux の drive も進まない。観察・撮影の前に利用者に前面へ出してもらう
- **宣言のキーは 10 文字未満にする**: Gitleaks の `generic-api-key` が `"key": "<10 文字以上の識別子>"` に当たり、push の前の検査で止まる。この子は P3 の宣言のキーを短くし、旧 state を控えて `--adopt` で引き取った（記録 10 章）
- **駆動の Component は駆動される Slot と同じ state に置く**: resoloop の参照（`$slot-member:`）も Flux の `drive` も、同じ state の中のキーしか結べない。地区の Slot を動かすなら、駆動の Component（`Spinner`・中継の `ValueMultiDriver` など）は `district.add_drivers` で地区の宣言に足す（キーは `p3_` で始める）。ProtoFlux のモジュールは `P3_Gimmicks` の下に配備する（地区の数を崩さない）
- **Flux の drive は Component のメンバーだけ**: Slot の `Position`・`Rotation` を動かすときは中継（`ValueMultiDriver<T>` の `Drives` に Slot のメンバー、`Value` を drive）を置く。`Value` は `initialFields` に基準の値
- **Flux のマニフェストの worldState は 1 つ**: 1 つのモジュールが結べるのは 1 つの地区の state だけ。複数の地区を動かすモジュールは、地区ごとに分けるか、値を DynamicVariable で渡す
- **計測の途中で背面に回ることがある**: 背面では回転が単位回転・止まった値に見える。`verify_live.py` は G13 の速さ、`--param-check` は止める前の回転で気付けるので、外れたら利用者に前面へ出してもらって測り直す（この子でも 1 回あった）
- **動いている間の観察は Component ごとに時刻がずれる**: 1 回の `observe` でも Component を順に読むので、同じ物の位置と回転が別の Component だと、式との一致は見られない。式は時刻を止めた標本（周期の値を 0）で確かめる
- **`managedFields` を付けた Slot の基準姿勢を変えるとき**: 宣言の位置・回転は作るときだけ使われ、apply し直しても既存の Slot には書かない。基準姿勢を変えるなら、駆動の中継の `Value` の初期値・`Spinner._offset` と合わせて、`component set` か作り直しで反映する
- **W08 の検査（`modeling/p2_static/verify_live.py`）は W09R 以降に既知の 11 件で失敗する**: Meshy の素材の宣言の数・扉の置き直し・古い蝶番の値（記録 11 章）。P3 の変更で増えていないかは、`rest_pose` を外した結果と比べる。`review/p2_static/live_checks.json` は W09R の検査が W08 の基準の数として読むので書き換えない
