## 5. 未解決事項・後続タスクへの注意点

- **座標変換規則 (`docs/conventions.md` / `docs/p0-report.md`)**:
  - Blender `(x, y, z)`（右手系 Z-up）は `resoloop blender export` により Resonite `(x, z, y)`（左手系 Y-up）へ変換される。Blender の `+Z`（上）が Resonite `+Y`、`+Y`（奥）が Resonite `+Z` になる。
  - Blender の `+Z` 軸まわり回転 `+θ` は Resonite の `Y` 軸まわり回転 `-θ` になる。
- **末端 Empty（`attachment_point` 等）のエクスポート挙動**:
  - `resoloop blender export --preserve-hierarchy` は、子孫に Mesh を持つ Empty（`AssetRoot` や `MotionRoot`）は Resonite Slot として保持するが、子孫に Mesh を持たない末端 Empty（`P0_PivotGate_001_Hook` など）は `model.apply.json` から省略する。
  - 後続の `W01`〜`W09` では、`assets/manifest/<key>.json` の `parts` (`role: "attachment_point"`) に `pivot_local` を必ず記録すること。Resonite 上にも空 Slot として残したい場合は微小なダミーメッシュを持たせるか apply plan 側で補うこと。
- **Resonite バックアップコマンド (`resoloop import`) の注意**:
  - `resoloop import Root` は `IMPORT_ROOT_FORBIDDEN` で拒否されるため、バックアップ時は `resoloop hierarchy` や `resoloop find` で確認した `Root` 直下の対象 Slot ID を指定すること。
- **検証ツールの使い方**:
  - 後続の `W01`〜`W09` で `layout/world_layout.json`、`layout/areas/<key>.json`、`assets/manifest/<key>.json`、`blender/<key>/<key>.blend` を追加した際、そのまま `uv run python tools/check_data.py` および `uv run python tools/check_blend.py` で自動検査される。

## 7. 自己判断で決めた項目と理由

- **小規模検証アセットの配置先 (`key = probe`)**:
  - W00 では `layout/areas/` や `assets/manifest/` が変更禁止範囲に指定されているため、probe 用のレイアウト・マニフェスト見本は許可範囲内の `modeling/probe/probe_layout.json` および `modeling/probe/probe_manifest.json` に配置し、`tools/check_data.py` で本番ディレクトリ（`layout/areas/`, `assets/manifest/`）と併せてスキーマ・整合性検査を行う構成とした。
- **`tools/check_blend.py` の画像検査基準**:
  - `.blend` 内の外部ファイル参照テクスチャは `packed_file` でパックされているか、または参照先ファイルが実在することを必須とし、未使用（`users == 0`）データブロックの残留をエラーとして検出する仕様とした。
- **`exports/` の Git 追跡範囲**:
  - `.blend` と `review/` 画像はすべて Git にコミットし、`exports/` 配下は検証サマリである `exports/**/report.json` のみを Git にコミットして、再生成可能なバンドル本体（`exports/**/*.apply.json`, `exports/**/*.mesh.json`, `exports/**/tex_*.png`）は `.gitignore` で除外する設定とした（リポジトリ肥大化防止および `model.apply.json` 内の識別子に対する Gitleaks `generic-api-key` 誤検出防止のため）。
